== Intro

Documentation of the requirements of the Crawl-Roster.
Describing Features and functionality of the application.

== Goals

The general goals that the app strives to achieve

=== Functional Suitability / Flexibility / Usability

The plattform must support the DGB (and possible other organizations) with managing and organizing the events.
For this the plattform needs to provide the required functionality and behavior as expected from it’s users.

Interactions should be clear for the users, behavior and actions should be clear and understandable
as the users have different levels of know-how regarding the plattform, the organization and to technology.

The plattform should provide the users, admins and organizers a certain amount of flexibility
as last minute changes are a common occurrence and the plattform should not hinder the process and stand in the way of events.

=== Reliability

The organization and the maintenance of the app is done by hobbyists.
The current and the new app is and will be maintained by a small group of devs in their spare time.

So the app should observe a low failure rate, provide a degree of fault tolerance when discord integration is not available.

=== Maintainability

An important secondary goal is to achieve easy to maintain application,
that requires low developer operational oversight.

== Scope

The application should be a companion app that enables the organization and management of events and the groups within an event for role-playing earnings.

The applications concerns itself with:

* Integration into Discord via bot - datasync and bot commands.
* Providing support with creating and managing events for admins / organizers.
* Providing support with creating and managing tables within an event for GMs/DMs.
* Allows users to keep a simple profile that aides with the coordination of tables.
* Allow the users to interact with the system via the bot in the discord client without needing to change the application.
* Provide the admins statistics of events.
* As a secondary priority, provide the functionality via WEB GUI

It will not:

* Manage user accounts, Discord ist the primary IDP.
* Replicate core Discord features like a full user profile.
* Replicate a chat - coordination of the events/tables happens in discord in the channels/threads.

== Constraints

=== Organizational Constraints

* The DGB is loosely organized and there are some core organizers but the community itself is loosely linked through the shared interest. Community consensus is important.

=== Technical Constraints

* Discord is used to organize the guild, the events, so the Discord integration is essential.
* Users must not need to create a dedicated account for the app, so Discord is used as IDP.
